# NHANES Diabetes / Prediabetes Risk Prediction

A 6-model stacking ensemble for diabetes/prediabetes risk prediction, trained
on NHANES 2011–2018 (cycles G–J, n=23,825) and validated on a fully
held-out, later survey cycle, NHANES 2021–2023 (cycle L, n=8,153) — a
realistic distribution-shift test, not a random train/test split of the
same cycle.

**Live demo:** [huggingface.co/spaces/mahmudsiyam/nhanes-health-prediction](https://huggingface.co/spaces/mahmudsiyam/nhanes-health-prediction)

| | |
|---|---|
| **Task** | Binary classification — diabetes/prediabetes (HbA1c ≥ 6.5% or fasting glucose ≥ 126 mg/dL) |
| **Training data** | NHANES cycles G–J (2011–2018), n = 23,825, prevalence 12.91% |
| **Validation data** | NHANES cycle L (2021–2023), n = 8,153, prevalence 10.25% |
| **Validation ROC-AUC** | **0.895** (95% CI 0.886–0.903) — stacking ensemble |
| **Base models** | LightGBM, XGBoost, FT-Transformer, Random Forest, Gradient Boosting, SVM |
| **Meta-learner** | Logistic regression on Platt-calibrated base-model probabilities |

## Why a held-out survey cycle, not a random split

Training on G–J and validating on L means the model is tested on people
surveyed years later, under a different sampling frame — closer to how
the model would actually be used than a random split of one cycle would
be. A Kolmogorov–Smirnov drift report (`ks_drift_report.csv`, generated by
`nhanes_dataset_preparation_v3.ipynb`) confirms which features shifted
between cycles, so the validation numbers below aren't inflated by
same-cycle leakage.

Note the single best LightGBM model edges out the stack on raw ROC-AUC —
expected for a well-tuned gradient-boosted tree on tabular data. The
ensemble's case is calibration (lowest ECE alongside FT-Transformer and
GBM) and specificity (0.925, the highest of any model), which matters
more than ROC-AUC alone for a screening tool where false positives carry
a real downstream cost.

## Methodology

- **Leak-free preprocessing**: training-set medians fit once, applied to
  both train and validation; no validation-set statistics ever touch the
  training pipeline.
- **Survey-weight handling**: NHANES 4-year combined exam weights computed
  from per-cycle 2-year weights; refusal/don't-know codes (7, 9, 77, 99,
  777, 999) converted to NaN before imputation; blood-pressure module
  column renames (`BPX_*` vs `BPXO_*` for cycle L) handled explicitly.
- **Calibration**: each base model's raw probability is Platt-scaled
  (1-feature logistic regression fit on a held-out 10% calibration split)
  before entering the meta-learner.
- **Leakage exclusion**: `LBXSCR`, `LBXSUA`, `LBXSAL` are dropped from the
  feature set as leakage-suspect (clinically entangled with the diabetes
  workup itself).
- **Robustness checks**: feature-group ablation, base-model leave-one-out,
  3-seed stability, threshold-sensitivity, and calibration-ablation
  analyses are all included (see `assets/tables/`).

## Running locally

```bash
git clone https://github.com/alm03806-dev/nhanes-health-prediction.git
cd nhanes-health-prediction
pip install -r requirements.txt
python app.py
```

The Model Performance and Results Dashboard tabs work immediately. The
Risk Prediction tab needs the trained model bundle in `models/` first —
see [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md) for how to generate it from
the Kaggle training run.
